# 12. 교사 계정과 "수업 단위" 구조 — 계획 (11/14 초안, 아직 구현 안 함)

> 한 줄 요약: 교사 코드 하나를 모두 같이 쓰는 지금 구조를 **교사별 계정 + 내 수행평가만 보기**로 바꾸고, "학교 전체 반을 한꺼번에 보는 화면" 대신 **선생님 한 분이 수업 시간마다 반을 열고 닫는 흐름**으로 바꾼다.

## 지금 구조의 문제

| 문제 | 지금 | 왜 문제인가 |
|---|---|---|
| 교사 코드가 하나 | `TEACHER_CODE` 하나로 누구나 교사 화면 입장 | 코드를 아는 사람은 **모든 교사의 모든 학생 리포트**를 봄. 학생 개인정보·평가 정보 노출 |
| 수행평가에 주인이 없음 | `ExamDef`에 만든 교사 정보 없음 | "내가 만든 수행평가만" 거를 수 없음 |
| 학교 전체 대시보드가 첫 화면 | 12개 반 × 4과목을 한꺼번에 보여 줌 | 실제로는 교사 한 명이 자기 과목·자기 반만 봄. 시연용 "학교 운영자" 화면에 가까움 |
| 시험이 항상 열려 있음 | 배포한 반 학생은 언제든 시작 가능 | 수행평가는 **수업 시간에만** 열려야 함. 다른 반 수업 시간에 미리 들어가 볼 수 있음 |

## 바꿀 구조

### 1) 교사 계정

- `dotori_teachers` 표: `id`, `email`, `name`, `school`, `subjects`, `password_hash`(scrypt), `created_at`
- 가입: 이메일 + 비밀번호 + 이름 (해커톤 범위에서는 이메일 인증 생략, 학교 초대 코드 하나로 가입만 막음 → 기존 `TEACHER_CODE`를 "가입 코드"로 재사용)
- 로그인 쿠키: 지금의 HMAC 쿠키에 `teacherId`를 넣어 서명 (`dotori_teacher` = `teacherId.만료.서명`)
- 시연 계정: `demo@dotori.school` (기존 가상 데이터 전부 이 교사 소유로 옮김)

### 2) 내 것만 보기 (권한)

- `ExamDef.ownerId` 추가. 수행평가 만들기 → 로그인한 교사가 주인
- 교사 API는 모두 `ownerId === 나`인 수행평가와 그 응시 기록만 돌려줌
  - `GET /api/teacher/school` → `GET /api/teacher/home` (내 수행평가 + 내 수업만)
  - `GET /api/report/:studentId`, `/api/report/class` → 그 기록의 수행평가 주인이 나일 때만 (아니면 404, 존재 여부도 숨김)
- 기본 제공 4개 수행평가는 "예시"로 누구나 복사해서 내 것으로 만들 수 있게 (원본 열람은 불가)

### 3) 수업(세션) 단위 흐름

```
수행평가 만들기 (1번)
  └─ 수업 열기: 2학년 3반 · 3교시  → 입장 코드 6자리 (예: 482 913) + QR
        학생: 코드 + 학번 + 이름 → 그 수업에만 응시
        교사: 이 수업 실시간 화면 (입장·질문·제출 현황)
     수업 닫기 → 새 입장·질문 막힘, 리포트만 남음
  └─ 다음 시간: 2학년 4반 · 5교시 → 새 입장 코드 …
```

- `dotori_sessions` 표: `id`, `exam_id`, `owner_id`, `class_label`(자유 입력, "2-3" 또는 "3교시 A반"), `code`, `opened_at`, `closed_at`
- 응시 기록에 `sessionId` 추가. `attemptId` = `세션ID_학번` (같은 학생이 같은 수행평가를 다른 수업에서 다시 봐도 안 섞임)
- 학생 시작 화면: 반 고르기 대신 **입장 코드 입력** 한 칸. 코드가 닫힌 수업이면 "수업이 끝났어요"
- 교사 첫 화면: ① 지금 열린 수업 (실시간) ② 내 수행평가 목록 (수업 열기 버튼) ③ 지난 수업 리포트
- 학교 전체 대시보드는 없앰 (시연 때는 데모 교사의 수업 여러 개로 같은 그림을 보여 줄 수 있음)

### 4) 학생 마이페이지

- 지금처럼 학번 + 이름으로 내 기록만. 수업이 여러 개면 수업별로 카드
- 실서비스라면 학생도 학교 계정(슈퍼스쿨 SSO)으로 바꿔야 함 → P2 설명용

## 작업 순서 (예상 1~1.5일)

1. SQL: `dotori_teachers`, `dotori_sessions` 표 + `dotori_exams.owner_id`, `dotori_attempts.session_id` 칸 (사용자가 Supabase SQL Editor에서 한 번 실행)
2. 교사 가입·로그인·로그아웃 API, 쿠키에 teacherId
3. 교사 API 전부 소유자 검사 (`requireTeacher()` → `requireTeacher(): Promise<Teacher>`)
4. 수업 열기/닫기 API, 입장 코드로 시작하는 `exam/start`
5. 화면: 교사 첫 화면 다시 짜기, 수업 실시간 화면, 학생 입장 코드 화면
6. 기존 가상 데이터 → 데모 교사 소유 + 반마다 "지난 수업"으로 옮기는 스크립트
7. 문서 (API.md, 06-data-model, 03-teacher-report, README)

## 확인 필요 (사용자 결정)

- 교사 가입을 막는 방법: 가입 코드 하나 (빠름) vs 관리자가 계정 발급
- 학생 입장: 입장 코드 6자리 (권장) vs 지금처럼 반 고르기 유지 + 수업 시간만 열림
- 기존 "학교 전체" 화면을 발표용으로 남길지
