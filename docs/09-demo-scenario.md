## 시연 6단계 (PDF 원문)

| # | 주체 | 동작 | 보여 줄 기능 | 우선순위 |
|---|---|---|---|---|
| 1 | 교사 | 슈퍼스쿨 바로가기로 「진달래꽃」 수행평가를 연다 | 슈퍼스쿨 바로가기 링크 | 링크(2장) / 연동은 P2 |
| 2 | 학생 | 본인 확인 → 개요 4항목 작성 (🔄 + 항목별 도토리 목표 정하기) | 🔄 학번·이름 + 기록 안내 동의 (페이스페이 없앰) | 모의 / P0 |
| 3 | 학생 | 둘째 문단을 드래그해 "근거가 약한 부분을 하나만 짚어 주세요" → 도토리가 넘어짐 → AI 답 → 글 수정 | 글쓰기+질문창, 도토리 차감·애니메이션, AI 답변 | P0 |
| 4 | 학생 | "감상문을 써 주세요" → 차단, 도토리 그대로 | 대신 작성 차단 | P0 |
| 5 | 학생 | 성찰지에서 항목별 도토리 그래프(🔄 목표 vs 실제) 확인 → 제출 | 성찰지 단계 | P0 |
| 6 | 교사 | 리포트에서 메모를 누르면 질문 전후가 펼쳐짐 → **"글은 같아 보여도, 과정은 다릅니다."** | 교사 리포트 메모 + 전후 비교 | P0 |

## 미리 만들 가상 데이터

🔄 11/13 교사팀이 만든 가상 데이터로 교체 (`scripts/demo-data/teacher-demo-students.json`, `npm run seed:demo`)

| 학생 | 계획 → 실제 허용 | 차단 | 특징 |
|---|---|---|---|
| S01 가상학생A | 3 → 2 | 0 | 필요한 질문 후 스스로 해석을 보완함 |
| S02 가상학생B | 4 → 11 | 0 | 고쳐쓰기 질문이 늘어나고 중복 질문도 경험함 |
| S03 가상학생C | 5 → 6 | 2 | "대신 써 줘"를 두 번 시도함, 질문 방식의 적절성을 고민함 |

- 질문 수가 많거나 계획과 다르다는 이유만으로 부적절하다고 보지 않는다 (교사팀 원칙)
- stage·type은 교사팀이 사람이 붙인 예시 값이다 (AI 자동 분류 결과 아님)
- **가상 학생만 사용** (10장 원칙)

## 시연 전 체크리스트

시연 흐름에서 도출:

- [ ] 슈퍼스쿨 교사 홈 바로가기 링크(또는 대체 화면)에서 교사 리포트/수행평가로 이동된다
- [ ] 시험 시작 화면에 본인 확인 모의 화면과 기록 안내 문구가 보인다
- [ ] 개요 4항목과 항목별 도토리 목표를 입력·저장할 수 있다
- [ ] 둘째 문단 드래그 → 질문 → 확인창 → 도토리 넘어짐 → AI 답이 끊김 없이 동작한다 (답 길이가 시연에 적당한지 확인)
- [ ] "감상문을 써 주세요" 입력 시 차단 문구가 나오고 도토리 수가 그대로다
- [ ] 성찰지 막대그래프에 항목별 목표 vs 실제 도토리 수가 반영된다
- [ ] `GET /api/health/llm`으로 LLM 연결이 확인된다 (🔄 교사 로그인 후에만 열림 — 열 때마다 AI 비용이 들어서)
- [ ] 시연 전에 시연용 학생의 `data/attempts/<ID>.json`을 지워 새로 시작할 수 있다 (같은 ID로 시작하면 기존 응시를 이어서 함)
- [ ] 제출 후 교사 리포트에서 메모 클릭 시 AI 답·직전 글·직후 글(추가 초록/삭제 빨강)이 펼쳐진다
- [ ] 학생 화면 어디에도 메모·분류·작성 경로가 보이지 않는다
- [ ] 가상 학생 S01~S03 데이터가 미리 저장되어 리포트에서 열린다
- [ ] 실제 학생 정보가 화면·데이터에 없다
- [ ] LLM API 키·네트워크가 시연 장소에서 동작한다 (LLM 장애 시 대비책: TBD(확인 필요))
- [ ] 마지막 멘트: "글은 같아 보여도, 과정은 다릅니다."
